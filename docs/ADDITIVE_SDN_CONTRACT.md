Public-firewall policy PUT sends exactly `expected_generation`, `group_ids`, `desired_state` and its original idempotency header. MCP-only `acknowledge_removal` and `acknowledge_no_inbound` are never sent to the backend. Before a present assignment MCP reads current returned `public_eligible` groups and rules. Unknown/ineligible groups are refused. No-ingress assignments require deliberate acknowledgement and can interrupt existing inbound-origin SSH. Any ingress rule is not proof of SSH reachability. Retry has no idempotency header or mutation arguments beyond the service ID. Group bootstrap creates an unbound project-wide group without NIC enrollment.

Public-firewall protection requires fresh backend `protected` evidence. Managed TLS `managed_tls` is first-listener intake eligibility and becomes unavailable after registration; listener TLS state governs certificate adoption/renewal. A terminal `tls_request` operation does not mean the certificate is ready, and certificate readiness does not establish traffic health. Poll the load balancer itself.

Responses use the reviewed secret projection for VPN, public firewall and load balancers. Private keys and PSKs are never accepted for these new interfaces. Typed 423 service-lock codes/reasons and safe unlock metadata remain available while arbitrary error detail is withheld.

No endpoint, customer mutation, fleet admission, staging change or deployment is executed by this MCP implementation. The additive runtime must remain blocked until root selects a backend batch containing all matching APIs, migrations and read contracts; the prepared VPN/dependency artifact has no such additive dependency.


One VPN product: new account quotes omit the optional compatibility tier code. The current canonical product comes from its Firecracker-plan-backed backend price row; `standard` and legacy `full_exit` are internal compatibility/proof-chain identifiers. The sellable catalogue suppresses only explicitly deprecated VPN alias rows, while preserving canonical order prices, distinct `renew_periods`, other products, existing/legacy quote receipts and original-key recovery. Additional traffic uses the separate traffic-pack quote and common checkout.

Shared SG rule edits require current `public_edit_impact.token` after explicit approval of all current/held public consumers. It is a public snapshot digest bound to group revision and consumer state; the secret projection preserves only its safe count and exact hex64 digest. `public_impact_ack` remains in the backend request/hash and must not change when recovering an accepted original key. Missing/stale impact conditions are returned without mutation or automatic retry. Name-only unchanged rules and private/unbound updates retain omission behavior. This requires backend `87f3852f62249ab290a924646dd176b7d628eb04` in addition to the separate mutation/lifecycle pin.


A pending managed TLS first listener can be cancelled through the existing listener DELETE only before any certificate adoption/runtime publication, using its current resource generation and original key. Read the LB afterward; a distinct corrected first-listener add uses a new intent key and current intake eligibility. Registration/cancellation advance resource generation without publishing a runtime intent. Issued/active last listeners retain the backend refusal. This recovery requires the final LB pending-cancellation backend follow-up; no new endpoint or caller certificate/private-key authority is introduced.
