# Official MCP Registry

Use the repository-root `server.json`; do not maintain a second manifest here.
The intended name is `com.vpsnet/vpsnet`, with the public Streamable HTTP remote
`https://mcp.vpsnet.com/mcp`. Set its version to the released connector version
before publishing. A remote-only registry record does not require an npm
package or package ownership metadata.

1. Install the current `mcp-publisher` from the official registry project and
   inspect `mcp-publisher --help`.
2. Verify control of `vpsnet.com` using the documented DNS or HTTP flow. DNS
   proof goes at the domain apex; HTTP proof is served at
   `https://vpsnet.com/.well-known/mcp-registry-auth`. Generate a real publisher
   key securely, keep its private part outside Git, and use the exact public
   proof generated by that flow.
3. Log in using `mcp-publisher login dns --domain vpsnet.com` or the documented
   HTTP equivalent, with the key arguments required by the installed CLI.
   Follow the official authentication instructions for the complete command.
   GitHub login alone does not grant the `com.vpsnet` namespace.
4. From the repository root, run `mcp-publisher publish` only after release
   approval. Confirm the returned server name and version.
5. Verify the published record with:

   ```sh
   curl --fail --get 'https://registry.modelcontextprotocol.io/v0.1/servers' \
     --data-urlencode 'search=com.vpsnet/vpsnet'
   ```

Registry publisher authentication is separate from customer OAuth used to
connect to the MCP endpoint. Do not add a shared bearer token to `server.json`.
After publication, use the [GitHub nomination](../github-registry/request.md).

Sources: [Authentication](https://modelcontextprotocol.io/registry/authentication),
[remote servers](https://modelcontextprotocol.io/registry/remote-servers),
[publisher](https://github.com/modelcontextprotocol/registry/tree/main/cmd/publisher).
