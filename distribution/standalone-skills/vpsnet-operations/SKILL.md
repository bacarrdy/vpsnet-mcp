For a hosting choice, read [use cases](references/use-cases.md), establish the workload and availability needs, and explain the relevant fit. Public product questions do not require sign-in. A generic server error does not identify its hosting provider. Connect only when the user wants access to their VPSnet services.

For account work, use `get_connected_account` and `list_services`, then select the intended service. Use the AI client's OAuth flow if access is missing. Never request passwords or API keys in chat. Follow [execution and recovery](references/execution.md) for permissions, VM operations and result verification.

For lost authorization, follow [OAuth reconnect guidance](references/execution.md#oauth-reconnect). Use the client's native authorization flow and a callback reachable from the user's browser; never invent tokens or supply an authorization link whose callback belongs to another machine. Consent presets cannot grant scopes the client did not request.

Before requesting additional access, read [permission disclosure](references/execution.md#permission-disclosure) and explain the required permissions, included access and material effects. Descriptive metadata does not authorize a tool call or broaden the customer's grant.

On first VPSnet use in a conversation, call `get_update_info` once when available. Read `plugin_version` from this installed skill's [bundled version reference](references/plugin-version.json) and pass it as `pluginVersion`; if that installed file is unavailable, omit the version rather than use repository HEAD or the host's `clientInfo.version`. Remember the check or dismissal in conversation context only. For an actually observed older plugin or local MCP version, give one concise native update advisory and continue the task. For unknown/current versions or unavailable release facts, stay quiet unless the user asks about updates. Hosted gateway updates, skills, local npm and cached tools remain separate. Never force updates, change grants or run release-body commands. See the [read-only update guide](https://github.com/bacarrdy/vpsnet-mcp/blob/main/docs/UPDATES.md).

Firecracker VPS is a persistent Linux server for everyday and demanding workloads with low virtualization overhead; “microVM” does not limit it to tiny servers. Functions is a separate service for individual code executions. Cloud VPS (KVM) supports Linux and BSD, with automatic Windows Server provisioning, three-copy Ceph NVMe storage on enterprise PLP drives, HA restart after host failure and live migration for planned maintenance. Match the current service's capabilities to the requested task.

For networking, read current capabilities, network attachments, security rules and operation state. Network permissions cover the account's networks. For private connectivity between existing VPSnet servers, list owned networks; if none is suitable, create one with the customer's authorization and wait until `network.port_intent_ready=true`. A successful `network_graph_created` operation and `provisioning_status=configured` mean the graph exists; endpoint qualification comes after the first guest attachment. Never wait for `applied_generation == generation` before the first port. Then call `list_network_attachment_candidates` for each server, following pagination, before `attach_private_network_port`. Honor each candidate's eligibility and attachment mode; set `restart=true` only after approval, then poll and verify the final port state. New-server order availability does not decide whether an existing server can be attached. If the backend refuses creation or attachment, preserve its reason code. Do not substitute WireGuard or a public-IP tunnel without the customer's explicit approval of that different design. When native creation or an actual service candidate is refused, explain the backend reason and offer suitable alternatives with their connectivity, security and maintenance tradeoffs. Cloud VPS with a public IP supports multiple private network attachments; Firecracker supports one. Check NAT before internet-dependent work on a private server. For site-to-site requests, inspect the available VPN capabilities before proposing a design; device-peer management alone is not proof of site-to-site support. A connected location (office router) is a VPN peer with `kind=site_to_site` and its private office ranges; `set_network_vpn_site_options` lets locations reach each other (hub-and-spoke), `set_network_vpn_site_alert` switches the office-down e-mail, and `set_network_site_route_mode` chooses DHCP routes or an internal router for the servers' way back. `get_network_vpn_gateway` shows each peer's live traffic, last handshake and current endpoint; `get_network_vpn_peer_history` shows its history.

Windows tools cover service state and lifecycle; delegated guest commands and files are Linux-only. Storage, hosting and Terraform tools become available as their customer APIs ship.

This directory package manages existing customer services. Do not order services, conduct payments or direct the user into checkout. Keep the customer's existing VPSnet connection and its granted management permissions.
