# VPSnet

Use VPSnet for the customer's existing VPSnet services. Public hosting questions do not require a connection. For account work, use the client's browser OAuth flow, then inspect `get_connected_account` and `list_services` before selecting the target. Never ask for passwords, API keys or access tokens in chat.

Use the bundled VPSnet operations, deployment, troubleshooting and Functions skills for their respective tasks. Read current capabilities and the application catalog before acting. An accepted operation is pending until its final result and the requested outcome have been checked. Keep operation keys stable when reconnecting or retrying.

Services are limited to the customer's selection. Linux files and commands require separate permission. Network, Functions, DNS, domain and certificate permissions cover account resources. Windows support covers service state and lifecycle. Functions execution requires separate consent to metered usage and a daily account usage ceiling. Purchases depend on the connected application and its advertised tools. Where available, use the same connection with separate purchase permissions, spending limits and explicit approval of the final balance charge.

If access or a capability is missing, explain the limitation and let the customer adjust the OAuth grant. Report tool errors and pending operations accurately. Do not infer success or broader API availability.
